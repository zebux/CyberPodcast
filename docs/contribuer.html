Proposer un podcast ou une ressource

Un podcast manque, un lien est mort, une fiche mérite une correction ? La contribution passe par GitHub : ouvrez une issue guidée ou envoyez une pull request. Les liens officiels et les flux vérifiés sont toujours prioritaires.

Critères de sélection

  • Le sujet principal est la cybersécurité, le cloud, le développement ou un sujet adjacent clairement utile à la communauté.
  • La ressource est publique, consultable sans accès privé et dispose d’un site officiel ou d’un flux RSS stable.
  • Le podcast est actif ou récemment actif ; un arrêt de publication peut être accepté si l’intérêt historique est expliqué.
  • Il n’existe pas déjà de fiche ou d’issue ouverte pour la même ressource.
  • Le contenu n’est ni illégal, ni haineux, ni trompeur, et les liens d’écoute renvoient vers les plateformes officielles.

Format attendu

Ajoutez une entrée dans le fichier source adapté : data/podcasts-cyber.yaml, data/podcasts-cloud.yaml ou data/podcasts-dev.yaml. Ne modifiez pas podcasts.yaml ni docs/ à la main : ils sont générés par le pipeline.

  - id: mon-podcast
    name: "Mon Podcast"
    category: ["Cybersécurité", "Blue Team"]
    language: fr
    host: "Prénom Nom"
    status: active
    website: https://exemple.fr
    rss: https://exemple.fr/feed.xml
    apple_podcast: https://podcasts.apple.com/...
    description: "Description courte et factuelle du podcast."
    platform: Ausha

Champs obligatoires

  • id : identifiant unique en kebab-case, en minuscules et sans accent.
  • name : nom public exact de la ressource.
  • category : au moins une catégorie, par exemple Cybersécurité, Cloud ou Développement.
  • language : fr ou en.
  • website ou rss : au moins une source vérifiable ; le flux RSS est fortement recommandé.

Les champs host, status, spotify, youtube, description et platform sont facultatifs mais améliorent la fiche générée.

Ouvrir une issue

Utilisez le modèle Nouvelle ressource et joignez les liens officiels, la catégorie, la langue et l’éventuel flux RSS. Pour un lien mort ou une erreur, choisissez le modèle Lien cassé ou Bug afin que le problème soit routé correctement.

Proposer une pull request

Forkuez le dépôt, créez une branche courte, modifiez uniquement le fichier data/podcasts-*.yaml concerné, puis lancez les vérifications locales :

python scripts/enrich_podcasts.py
python scripts/check_health.py
python scripts/render_html.py

Ouvrez ensuite la pull request avec le modèle fourni. Les fichiers générés doivent être inclus s’ils changent après le rendu.

Règles et sécurité

Le guide complet est dans CONTRIBUTING.md. Pour signaler une vulnérabilité, suivez SECURITY.md et n’exposez jamais de détails exploitables dans une issue publique.

Prêt à contribuer ?

Une proposition claire, même minimale, est toujours utile. Merci de garder les liens officiels à jour et de respecter le code de conduite du projet.
